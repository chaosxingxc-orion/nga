This supplement answers the owner's request to align metrics with the reference literature. It adds descriptive probability metrics to the existing R3 protocol, without changing selection thresholds, gates, splits, training, prompts, model choice, or the existing reported numbers. The original R3-SFT-PREREG remains normative. No supplementary metric chooses a model or authorizes a test read.

## Definition and scope

For each clean question, use the original option order, hard gold index y, and saved fp32 candidate scores s defined in R3 §3.2 (sum of label-continuation token log probabilities). Compute p = softmax(s) at fixed T=1 in CPU binary64 arithmetic. There is no temperature fitting, including on calibration or test. No clipping, probability floor, score-length normalization or option filtering is added. Reject empty populations, invalid gold indices, nonfinite scores and mismatched row lengths; do not silently drop questions. Unequal option counts are allowed. Single-option questions are valid and must be counted.

Each suite and partition is a separate panel. Test panels use the existing clean decision-v7 population of 1,200 questions and transfer-v4 population of 656; calibration, if reported, is the existing decision-v7 calibration partition of 1,148 questions. Development is explicitly labelled dev and cannot substitute for test. No cross-suite average, cross-seed pooling or changed mask is introduced. Each trained seed and each distinct K0 checkpoint has its own panel; QO retains drop input, PT retains its instruct base, and those control labels are explicit.

- **Accuracy**: first argmax of raw s equals y, exactly the R3 headline. Retain exact-score top-tie count. Separately count any question where first argmax of binary64 p differs from first argmax of s due to rounding; never silently relabel such a difference as perfect reference agreement.
- **Brier (sum)**: mean over questions of sum_i (p_i - 1[i=y])². Do not divide by the number of options. Binary Brier (p_true-y)² is a different convention and is not this field.
- **ECE10**: top confidence max(p), correctness from the R3 raw-score prediction. Edges are Python binary64 i*0.1 for i=0..9 followed by exactly 1.0, matching the reference verifier. Lower bound inclusive, upper bound exclusive except the final bin includes 1.0. For each bin contribute abs(sum(correct-confidence))/n. Report counts and mean confidence/accuracy per bin; empty-bin means are null, contribution zero.
- **NLL**: mean(logsumexp(s)-s_y), calculated as log(sum(exp(s-max(s)))) + (max(s)-s_y). This avoids avoidable cancellation and retains finite large loss when exp underflows. No probability floor is applied. If the mathematical value cannot be represented finitely, reject rather than return infinity or substitute a clipped value.

The standalone numerical function does not establish data population, option ordering, source identity or admission. Before publication a source consumer must verify the existing final ticket and report provenance, bind dataset/ordered keys, option identities, gold and score vectors, protocol and model bytes; verify the existing headline; and attach a separately hash-bound supplementary output. Source changes during reconstruction must reject. It must never make a second inference/test authorization, mutate frozen producer reports, or read a test dataset before existing final admission. This integration is not complete merely because the numerical function passes tests.

## Alignment and interpretation

Compare T=1 fields with the reference raw-T1 panel only when dataset hashes, clean masks, question identities, denominator, option order, gold labels and formula agree. Native/serving temperature reference panels remain separate and cannot be relabelled T=1. The NGA label-continuation readout and Kev pointer head are different model interfaces even with the same metric. Brier/ECE agreement does not establish paired correctness or decision consistency. Published aggregate reference values permit aggregate comparison only; paired gains require genuine corresponding item-level predictions.

These measures relate to defect-registry rows 1/17 (level interpretation), and contextualize confidence failures in rows 5/16 (fallback/comparability); they do not directly test refusal, menu invariance or unknown detection. Unconstrained empirical Brier/NLL minima are zero from a gold lookup table (NLL approaches zero for finite scores). Perfect ECE can also arise from an uninformative constant predictor matching its aggregate correctness. Therefore no calibration-only success claim is allowed: retain the existing clean accuracy floor and question-only/empty-input controls as discrimination counterparts, with their current definitions. No invariance claim is introduced.

## Validation and publication conditions

Use analytic cases (uniform and confident wrong predictions), variable option counts, ties, exact ECE boundary tests, translation invariance and large finite losses. Compare ordinary finite cases with the frozen reference metric implementation. Reject malformed inputs; test JSON finiteness. Independently review the specification, arithmetic and eventual source-consumer integration. Publish measured supplementary results only after actual final admission and reconstruction; until then label code/test results as engineering evidence.
