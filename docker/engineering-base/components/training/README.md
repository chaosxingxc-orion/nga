# Training component

The original `k1-full-train-v1` route remains in `training.py`. Its 0.8B checkpoint format and 3,116-step recipe are unchanged. `dispatcher.py` also accepts a separate `recipe_id` config and dispatches it to `family.py`; `family-schema-v2.json` is the closed component schema. The outer image adapter and host schema do not yet dispatch or admit the new route.

`family-registry-v2.json` retains the audited model-member inventory and plan/manifest pins for Qwen3.5 Base 0.8B, 2B, 4B and 9B. The registered LoRA pair counts are 186, 186, 248 and 248; trainable scalar counts are 10,822,656, 16,819,200, 32,464,896 and 43,278,336. The `topologies/` manifests bind ordered names, shapes and dtypes to the pinned image, authenticated configs and retained builder; the component checks their digests and exact sequence at model construction.

The route runs the pinned `train_r3.py` K1 code, with rank 16, alpha 32, dropout .05, AdamW lr 1e-4/weight decay .01, gradient clipping 1, OneCycleLR total 3,116/pct_start .1, ref kernel, non-reentrant checkpointing, max length 4096 and micro tokens 12000. `engineering_stop_after` is a required positive number of updates in this invocation, separate from the full scheduler. At step 3116 the route publishes an adapter from the terminal checkpoint, and a completed resume retries publication without another optimizer update. Periodic-save and stop-save overlap is suppressed within the same invocation.

Version 2 checkpoints bind recipe, model inventory and revision, dataset, source bytes and seed independently of output path. They include ordered parameter topology, optimizer, scheduler, next-step cursor and parent checkpoint hash. Input digest is checked before deserialization. Resume is restricted to the latest explicitly named checkpoint in the owned output, and the output owner is checked separately. Legacy checkpoints have no compatible identity and are explicitly unsupported; never strip identity to import them. Checkpoint state and the owner file require exclusive output ownership from the caller. NPU RNG seeding failures propagate; missing NPU APIs fail the production route. CPU diagnostic mode reports the missing API explicitly.

`family_qualification.py` is a small, frozen-base PEFT LoRA CPU fixture with the registered rank/alpha/dropout, optimizer and full scheduler. `test_family.py` compares six updates with 3+3 across separate processes, including each named preclip gradient, loss, AdamW and OneCycleLR states. It is not a Qwen run or NPU qualification. `trainer_cpu_probe.py` runs the actual trainer loop with a synthetic CPU model/data and NPU API substitution, and probes the original `Data.step_units` slicing without corpus access. Existing `qualification.py` remains the old two-step linear mechanics fixture.

Training release remains on HOLD. Independent review, root integration, host path validation, NPU dropout/checkpoint recomputation equivalence and measured bf16 gradient floors, and end-to-end progress/lease/terminal integration remain outstanding. Legacy import remains unsupported. See the local handoff for CPU qualification and its limitations.
