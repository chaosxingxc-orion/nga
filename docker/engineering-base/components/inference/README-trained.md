# Trained full-label inference component v1

This is a root-dispatched component API; image assembly and production qualification remain pending. `run(config, output)` accepts exactly `trained-schema.json` and an absolute output directory. The caller supplies an NPU execution environment; this component does not launch or manage a container. Registry, training code, native component and pinned native source must be installed in their existing relative layout. No loader is accepted from config.

To construct a panel without a circular dependency, first call `model_identity(config)` with `recipe_id`, `model`, and `adapter_publication` fields matching the schema. It verifies the complete registered base inventory and terminal checkpoint, then invokes the family publisher's existing read-only verification of its already-present `adapter` directory. It returns `(identity_object, model_sha256)`; identity includes recipe and revision, inventory, full checkpoint identity and digest, hashes of all four publication files, and unmerged frozen fp32 PEFT loading semantics. Preserve the object and digest. Use that digest as `model_sha256` in the existing native panel protocol contract, and supply the contract file hash, canonical contract hash, ordered requests hash and model digest in `panel`. The digest is not a base-only inventory digest.

The model manifest is the training family manifest `{model_id, files}` pinned by its file hash, and every file must match the selected registry recipe. `adapter_publication` requires a terminal checkpoint, its digest, the training seed and owner, and its published `adapter` directory. The checkpoint is read with `weights_only=True`; optimizer, schedule, topology, source and family identity are checked by the family validator. Publication validation compares all serialized PEFT config defaults and all adapter tensor values to that checkpoint. Paths must be absolute and symlink-free. Protect admitted artifacts against concurrent mutation; validation and loading are separate operations, so this API does not claim adversarial concurrent-writer isolation.

The dataset is newline-delimited native v2 requests (`i`, `qid`, `state`, `question`, `kind`, `options`), pinned by SHA-256 and count. Runtime is NPU, max length 8192, batch size 1, no truncation; the loader disables HF32, loads the base locally in fp32 with remote code disabled, freezes it, loads the exact PEFT publication locally, leaves it unmerged, and evaluates. Native full-label preparation, single forward, arithmetic and fp32 full-vocabulary item persistence are reused. The panel contract binds the combined model identity. Records use native v3 item format with the trained run identity and panel hash. The owned output contains `OWNER.json`, `items/`, `model-identity.json`, `predictions.json` (`nga-trained-predictions-v1`), `completion.json` (`nga-trained-completion-v1`), heartbeat and exit marker. Resume validates all committed records before loading weights, quarantines partial items, and refuses identity changes. The run identity also binds config, component, native component and native source hashes. `image_sha256` is supplied by the caller and bound into that identity; the caller must attest it.

Update panel generation to call the identity API before contract creation; teach export and score to accept trained completion/prediction schemas and retain combined `model_sha256`, contract and item receipt bindings end to end. Do not translate them to base-only model manifests or native base completion schemas. Add integration and rejection tests at each boundary and independently qualify numerical/runtime behavior on NPU before any scientific use. Root dispatch, export and trained score provenance are present in the working tree; they do not establish image assembly or NPU qualification.
