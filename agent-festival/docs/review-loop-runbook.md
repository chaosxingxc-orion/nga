## 一、一轮的标准做法

1. **开轮回放（保留率门）**：`python3 tools/replay.py` → 六面全 PASS 才开轮；任何 FAIL 先修面再开轮。
2. **定增量**：`git -C <repo> log --oneline <prev>..<head>` + `git diff --stat`——增量范围写进 prompt。
3. **派空白子**：§三 模板 + 增量范围。**零上下文**（不给历史裁决、不给既有结论）。
4. **标定轮（每 ~3 轮一次）**：`python3 tools/seed.py --family <已知族> --out <克隆> --keep` +
   `--family <ood> --out <克隆2> --keep`——派**独立**空白子审克隆（不知有植入）；
   检出情况记台账：`## R<N> 标定（植入 a+b，检出 x/y）`。
5. **清偿**：B/M 逐条修复；每条 M/B 清偿按台账头部协议带 token（**先跑后写，不许预报**）。
6. **收轮（条款双源）**：空白子报告尾部**提议 1-3 条下轮火力面条款**（它发现自己缺的检查）；
   修复者裁决：采纳→落 attack-corpus.md §二 或 pattern doc；驳回→记录理由。提案者≠下轮空白子。
7. **记账 + 提交**：台账 `## R<N> 复审记账`；本地提交。**推送 MR 须用户口令（逐次授权）。**

## 二、停机准则 v2

**3 连 0B/0M** + 开轮回放保留率 100%（机械）+ 标定检出率逐轮报告（近似度量——oracle
递归不消解，诚实声明）。连净计数的稀释博弈由回放+标定双指标对冲：审得越多≠检得越深，
检出率才是灵敏度。

## 三、空白子 prompt 模板（引用填充，<RANGE> 为唯一样板插值）

```
你是独立评审者（零上下文空白子，第 <N> 轮）。对 git 仓库 <REPO> 的 Go 测试代码增量做
4-lens + singularity 审查。

审查对象：git -C <REPO> diff <RANGE>。先看提交链再逐文件读。

方法论两把枪：
1. 4-lens：简单性/一致性/支撑性/保真度（doc 与代码、声明与事实互相对得上吗；每个声明
   有可当场复跑的机械证据吗；测试测的是它声称测的东西吗）。
2. singularity：问题重定义（守卫/断言实际测的是不是更容易的问题）+ 可达错误状态（构造
   具体输入或源码编辑使被宣称拦住的东西静默通过）。每个可疑点动手验证，不许只凭读码定级。

火力面：读 <REPO>/agent-festival/docs/attack-corpus.md（§二 判据×用例映射——机器面行
抽查突变验证，审查面行逐条过）与 <REPO>/agent-festival/docs/fixture-guard-pattern.md
（守卫六件形态）。协议见 <REPO>/agent-festival/docs/minor-ledger.md 头部（清偿证明协议+
修复义务协议——R56 起 M/B 清偿无 token=自动 M）。

基本卫生：gofmt / go vet / go test ./... -count=1 -race（<REPO>/agent-festival/go）。

输出：发现按 B/M/m 分级，附 文件:行号 + 你实际跑过的命令与输出；收尾 B/M/m 计数。
没有发现就明说。宁可错杀，不许客套——每个「没问题」都应是你验证过的。
报告尾部：提议 1-3 条下轮火力面条款（你发现本清单缺的检查）——修复者会裁决。
```
