# 件0：迁移事件身份契约（v1，2026-10-31）

> 约束件 2/4/5/6 的共享键。来源：NGA 总设计 §7.2（三身份）+ 12 号 §3（重放匹配）+
> 15 号 B4（载荷拒绝）+ singularity 碰撞分叉一（主脊载体）。六件全绿 ≠ 合体成立，
> 身份键断 = 各件全绿但合体断。

## 1. 事件身份（三层，NGA §7.2）

```json
{
  "business_request_id": "br-…",     // 业务请求：客户提交的已识别请求
  "evaluation_revision": "er-…",     // 评估修订：同一请求在新版本下的重评（新身份，链到原请求）
  "operation_id": "op-…"            // 业务操作：要幂等的外部效果单元（跨崩溃存活）
}
```

- 重试/恢复复用 `operation_id`（不是新身份）；新评估 = 新 `evaluation_revision`
- 问责三元组（D31：session/skill/role）与三层身份**并列携带**——业务身份与问责
  身份正交，join 点是账本事件

## 2. 幂等键语义（15 号 B4 + 12 号 §7）

- 幂等键 = `operation_id` + 请求载荷 digest（JCS(contract) 的 sha256——复用基座
  ContractHash 的形态与栈）
- **同键必同载荷**：digest 不匹配 → 拒绝匹配（「changed payload under the same
  key」是 14-A5 第四反例——一个同键换载荷也照收的键不叫幂等键）
- 首次见到键 → 采纳；再见同键同载荷 → 复用既有结果；同键异载荷 → 拒绝

## 3. 仲裁序记录（12 号 §2「recorded arbitration order」）

- 并发竞争的赢家序必须记进事件（`arbitration_seq` 单调递增）
- replay 重算时按记录序重放竞争，不重新仲裁（记录序是历史事实）
- 败者读既有结果/冲突态——不是错误

## 4. 版本绑定纪律（P5 五维 + 13 号 §5）

采纳事件必须携带其判定实际消费的版本：

```json
{
  "versions": {
    "evidence":  "…",   // 证据快照版本
    "rule":      "…",   // 判断规格/业务规则版本
    "model":     "…",   // S1 模型 checkpoint
    "readout":   "…",   // 读出接口版本
    "policy":    "…"    // 决策算子/采纳策略版本
  }
}
```

- **模型版本名不是其实际输出的替身**（12 号）——输出以记录形态保存在件 6 的
  记录族夹具，版本字段只做寻址
- replay 匹配键 = `operation_id` + digest + 依赖版本（12 号 §3 步 4）

## 5. 记录族输入的归属（S1 岔路裁决）

- 账本（件 4）：只承**采纳/效果事件**（带上述身份/键/版本）
- 记录族完整输入（模型实际返回/工具响应/guard 实耗/时间事件）：**件 6 夹具自备**
  ——不进账本 schema，账本保持精瘦

## 6. 单写者与不可互换性

- adopt 状态机（件 2）是账本采纳事件的**唯一写入方**；旁路直写 → 加载时拒绝
- 四操作（检视/控制重放/重评/活体恢复，12 号 §1）为**四个不可互换的结构化入口**
- replay（件 6）只读账本+记录族，永不写
