# C4 排序契约设计注记（修复批收尾，非实现）

> 出处：xingchao MR!2 评论① §6 + 企业级反馈 F-06（C4 行）；我方问 3 提案被正当击穿的两洞（11 号对账 §二.3）。本注记=设计方向，实现挂宿主侧联合作业（制品 B 链路第 4-5 步）。

## 两洞（认领）

我方「取代检查镜像 grantsCover」提案只覆盖 **dispatch 时点**：
1. **采纳阶段过期**：D1 采纳后、dispatch 前，D2 被采纳——D1 的 dispatch 请求进入「检查已过、提交未至」窗口；
2. **check-then-act 跨系统竞态**：live 有效修订集来自宿主、在机器锁外维护——机器的进程内锁管不了跨系统的序（10-walkthrough §8.2 自己要求 hold 与 dispatch 对同一相关状态排序，我方提案未提供）。

## 设计方向（三行控制语义复用 14-A4 模式，补排序）

- 宿主侧维护**单调版本的有效修订序**（哪个 D 当前生效是业务决定——框架不解释业务语义，宿主传入）；
- 机器执行双谓词：dispatch 时 `live 修订集不含本 op 绑定的 evaluation_revision → 拒发`（镜像 grantsCover）+ **采纳时** `本修订已被更新的已采纳修订取代 → 冲突事件`（镜像同 key 异载的 conflict 语义）；
- 排序契约：宿主的单调序是唯一真源，机器在两个时点消费的是同一序的快照——竞态窗口由宿主的单调性消灭（序不可回退，迟到 D1 的序 < D2，两时点皆拒）。

## 验收形态（制品 B 场景）

「旧提案迟到」场景：D2 采纳后 D1 dispatch → 拒发且 control 事件留痕（E3）；「请求已发出后新证据」场景：D2 在途、D3 采纳 → 在途 op 不受影响（钉照），新 op 走新修订。
