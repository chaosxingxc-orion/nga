## 一、Jev 输入契约 × 我方判断规格设计

### 他说得对不对（独立验证）

对，且其论强度超过我方既有立场。三个 Why 各自验证：

- **信息混杂/倾向污染**：与夏第一轮裁决理由 1（锚定污染）同源，方向正确。〔注意〕对方本轮并未引用夏的裁决——这是其立场独立推导到达同一点，属双方独立收敛的证据，应记录。
- **「封存不自动等于无偏差」「参数量小不自动意味着不能处理长输入」**：这两句是对方对自己潜在过度引申的自我克制，诚实度高。它同时堵住了两个方向的偷懒：用封存动作代替输入设计（我方风险），用参数量推导上下文上限（对方风险）。
- **「不能仅保留任务身份/版本就丢掉必要任务事实」**：这一句**正当击穿我方交互二的修正提案**。我方制品 A 修正二提议把「当前任务状态」改写为「任务身份/版本与卷宗」——按字面执行，补证阶段、已收材料、证据时间范围会从 S1 输入中消失，而这些能改变正确判断。我方的词级修正把澡盆里的孩子（必要任务事实）和洗澡水（活上下文）一起倒了。

### 深层结构

S2→S1 通道之争已历经三代形态：

| 代 | 形态 | 载体 | 可机检性 |
|---|---|---|---|
| 一 | 拓扑之争（封存 vs 活上下文 vs 受控交接） | 夏两轮裁决 | 否（裁量判据） |
| 二 | 词级之争（「任务状态」一词可否出现） | 我方交互二 | 弱（词形检查可绕过） |
| 三 | **字段级契约**（哪些字段经声明、实际消费、可追溯） | 对方本轮 Jev 输入契约 | **是**（字段在规格中或在/不在；消费版本有记录或无） |

第三代的胜利不是修辞胜利，是**判据形态的胜利**：只有字段级契约可以直接变成 schema 与检查器。夏的元原则「事前结构化优于事中裁量」在输入边界到达其终局形态。

### 与我们的碰撞点

**碰撞点 A：件 3 只是机器载体的一半**。`schema/judgment.schema.json` 定义的是判断**规格**（question/conventions/levels/candidate_set/rules/resolution/examples/scope/ownership——judgment.spec 面即"S1 要回答什么"），而判断**输入**（"S1 消费什么"——快照卷宗）在我方全仓**无 schema**。T0 喂给 S1 的是 ad-hoc Go 结构体 `creditEvidence`（e2e_test.go:25-29）——未版本化、未 schema 检查、字段集由测试作者随手定。对方输入契约要的正是缺失的那一半。0.2.0 路线图（judgment.schema.json:276 $comment）已列 `on_evidence_gap`+`channel` 两项；输入快照 schema 应为第三项，三件同批。

**碰撞点 B：机检设施已半存**。对方 How 段要求「记录选入、遗漏、转换与来源」——夏一轮的查询足迹/排除记录机制在 evidlog 已有机器面（`CheckCoverage` 的 Missing/Unaccounted 差集告警，evidlog.go:330-390）。快照字段的「实际消费可追溯」可复用同一底座：声明字段 ↔ evidlog 足迹的对账。这不是新机制，是既有机制的消费面扩展。

### 生态参照（frame-bench 结构级）

- **langgraph `Send`**（libs/langgraph/langgraph/types.py:738）：`Send(node, arg)` —— "the sent state **can differ from the core graph's state**"。当 langgraph 要一个节点消费特定输入时，不给它全量活状态，而是**逐目标组装的显式 arg**；map-reduce 正式依赖此形态。这是「结构化消费契约 vs 全量上下文」的生态先例：判定座的有界组装输入。

- 两处旁证指向同一结论：**生态早已收敛在「判定座=有界组装输入」上；我方 T0 的 ad-hoc creditEvidence 是异常点**，不是常态。

### singularity 判定

非奇点，是**收敛装置**——前提两条：①快照字段集归语义规约声明（否则「必要任务事实」变成运行时拼装的活上下文侧门，S2 倾向性表述可从「任务事实」门回流——可达坏状态具体化：`task_facts` 字段无声明边界 → S2 的总结句以「阶段说明」名义进快照 → 锚定门重开）；②字段对 evidlog 机检。两条都做，它就是夏两轮裁决的机器载体落地。

2. **反例对照表「循环再次合法进入…已钉」过度声明**：f02abc 表中该行的证据是「幂等键同键同载→reused 返回原结果非重执行」。但对方 D-02 的 Why 完全成立：固定图规定两轮补证时，**第一轮的网络重试**应复用第一轮（同执行实例），**第二轮因新补证条件进入**是新的逻辑工作。机器层的事实是：`ops` 以 operation_id 为键（adopt.go:105），同键同载→reused、同键异载→conflict——**机器自己从不区分「重试」与「新一轮进入」，这个区分完全由宿主通过发新键或发旧键来做**。我们没有测试过「循环下一轮合法进入是新的工作」这个分支（T0 无循环场景——0.1 图只有 seq/par，条件边/循环在 0.2.0，对方交付状态表也如实记录了这点）。该行正确标注：**未钉，待图级执行实例验证**。
3. **执行实例层缺失**：identity 三层（business_request/evaluation_revision/operation_id）中没有任何一层对应「节点的一次执行实例」。

### 生态参照（D-02 的现成解法）

**langgraph 的任务身份派生**（libs/langgraph/langgraph/pregel/main.py:4354）：

```python
def _update_task_id(checkpoint_id: str, i: int) -> str:
    return str(uuid5(UUID(checkpoint_id), INTERRUPT if i == 0 else f"{INTERRUPT}:{i}"))
```

任务 id = uuid5(检查点 id, 槽位)——**执行实例身份是从检查点（超步）派生的**：每个新超步/新检查点天然产生新任务 id（新一轮=新实例），同一超步内的重试保持同一 id。加上 `types.py:738` 的 `Send` 与 `base/__init__.py` 的 `put_writes`（写以 `(task_id, idx)` 为键、存储层去重，memory/__init__.py:502-505——"Savers keep one write per (task_id, idx), so updates sharing an id lose all but the first one's writes"），langgraph 用**派生方案**而不是新增身份产品实现了 D-02 要的三层区分。对方 How 段明说「具体标识可由 openJiuwen 与现有身份机制映射，不强制新增身份产品」——双方在此已同位。我方设计注记应采用同型方案：**执行实例 = f(运行, 节点, 迭代序)**，由宿主从图运行上下文派生，机器照单收键。

## 五、D-05 × C4 排序契约：单调性击穿

对方 D-05 的旧修订防护段：「读取 v2 并通过检查后，v3 生效，随后仍提交 v2，**并不违反版本单调性**。需要说明排序、条件提交或等效机制怎样排除该窗口。」

独立检验：我方制品 A 的 C4 方案是「宿主侧维护单调有效修订序作为唯一真源，机器在采纳与派发两个时点消费同一序的快照……竞态窗口由序的单调性消灭」。推演该方案的时序：机器在 Dispatch 时读取宿主序快照（D2 生效）→ 检查通过 → 提交 dispatch 事件。若在「检查通过」与「提交」之间宿主序前进到 D3——提交仍然发生，且**全程未违反任何单调性约束**（序本身单调、两次读数各自合法）。单调性只是序的**不变量**，不是提交的**条件**。对方击穿成立：我方注记的「消灭窗口」是过度声明，实际只做到了「窄化窗口」。

第一性修复：要闭合 check-then-act，检查必须进入提交的原子区——即**条件提交（CAS）**：派发提交携带它所验证的序版本号，宿主持序存储只接受「被检版本仍为当前有效版本」的提交（或 ≥ 且重新检查）。因序在宿主侧（机器锁管不了跨系统序——制品 A 已承认），CAS 边界必在宿主持序存储上；机器的配合面是：派发事件内**记录被检序版本**，使检查可审计、效果边界可复核。这条应替换 C4 设计注记的对应句。

### 深层发现：证明边界位移定律

我方 T0 的全部证明面相对其声称面**内移一层**：

| 声称 | 证明实际所在层 | 位移 |
|---|---|---|
| 零模型/零业务调用 | 计数器在 harness 座上 | harness≠适配器边界 |
| 返回原回执 | 存根重推导同一字符串 | 推导≠取回 |

| 循环下一轮合法进入 | 幂等键同键同载 reused | 操作判重≠实例判别 |
| 重启后等待恢复 | 账本状态恢复 | 状态恢复≠等待持续 |

上一轮的定律是「击穿分布与探针设施分布精确互补」（探针在代码层、击穿在声明层）；本轮的升级是同一条定律的递归应用：**探针层必须随声称层外移**——当声称从「机器语义正确」外移到「节点结果服务正确」时，探针（计数器/失败探针/重启）必须跟着外移到适配器边界与节点入口。对方场景 R 的配方（「把计数/失败探针放在实际适配边界，复用请求通过与正常执行相同的节点入口，再证明是入口主动选择了存储路径」）就是这条定律的工程化表达。

**langgraph 旁证**：`put_writes` 以 `(thread_id, checkpoint_ns, checkpoint_id)×(task_id, idx)` 为键的存储层写去重（memory/__init__.py:497-512）——重执行到达存储层时**由键主动裁决合并**，不依赖上层不重入。「入口主动选择存储路径」在生态里的对应物就是「写路径键控去重」——场景 R 要的正是这个形态。
