## 二、逐点碰撞（每点：事实 → 4-lens → singularity → 裁决）

### P1｜新文件首写 0644 绕 umask（邢超评论② §2 vs 我方 L14 裁决）

**事实**。adopt.go:494 `mode := os.FileMode(0o644)`，仅在文件已存在时改用 `info.Mode().Perm()`（:495-497），随后 `os.Chmod`（:498）——Chmod 不受 umask 限制，故 umask 077 主机上首写文件精确落 0644。evidlog.go:267-271 同构。临时文件本身是 `os.CreateTemp` 的 0600，Chmod(0644) 是在其上**显式加宽**的一步。minor-ledger L14 记录了裁决：「实现维持 0644 直设……syscall.Umask 进程级竞态不值」；增量评论（197874052）公开重申「审计可读性是记录在案的裁决」。

**4-lens**：
- Simplicity：0600 默认 + 保留现状是**更少代码**的选项（仅存在时才 Chmod）；0644 直设反而在 0600 之上加了一个加宽动作。失简方是我方。
- Consistency：组件在内存域是权限极严的（adopt.go:326-330 的 14-A4 撤销复检是全仓最严的权限面之一），在磁盘域却静默加宽可见性——同一组件两种安全姿态，内部不一致。
- Bearing：邢超探针可复现（umask 077 + 首写 → 断言 `Perm()&077==0`）；修前红修后绿可机械化。L14 裁决本身无探针。
- Fidelity：代码注释「audit readability is the recorded L9 umask ruling (2026-11-03), not an oversight」（adopt.go:492-493）——登记是诚实的，但**诚实登记了一个错误决定**；且该裁决的反驳对象是「0o666&^umask（umask 竞态不值）」，而邢超的提案是 0600 定值——**裁决回答了一个没人提出的反提案**。

**第一性原理**：默认值的决定权属于谁？部署方对本组件唯一的预建权限策略通道就是 umask（组件 API 只有 `Open(path)`，无权限参数）。组件用 Chmod 覆盖 umask = 没收部署方唯一的表达通道。可逆性不对称：部署方想要审计可读，建后一次显式 chmod 即得；部署方想要私有，无法用 umask 撤回组件的加宽。**不可逆方向的一方必须持有保守默认。**

**singularity**：可达坏状态成立（限制性 umask 主机 + 可遍历父目录 + 本机他账户 → 业务标识/查询选择器/证据引用可读）。采纳邢超方案不重定义问题。**判：真缺陷，非偏好之争。**

**裁决：邢超对。** L14 应推翻，修法=「存在则保留、不存在则 0600」（邢超最小方案），同时采纳他对 Stat 非-NotExist 错误应显式报错而非无声回退的附带意见。〔MR#1（51bab89）首写为 0600 的对照表：采纳邢超表格，未独立复现〕

### P2｜断尾重放再次放行已放行的操作（邢超评论② §3 vs TORN-TAIL DOCTRINE）

**事实链**（逐行核对）：`ledger.ParseLines` 对 EOF 处无换行的不可解析尾 silently `continue`（load.go:55-57、67-68）；`LoadDocument` 不回传任何损坏信号（load.go:80-89）；`adopt.Open` 恢复出 adopted 状态后，`Dispatch` 只检查 `state==StateAdopted` + grants 覆盖（adopt.go:323-330）→ 再次 dispatched；下一次 append 的重建还会**永久抹掉**残尾字节（adopt.go:438-470「a torn tail … is healed away on the next successful append」）。对照 evidlog：同样形状下 tornTail 被记忆、Append 拒写（evidlog.go:167-176）、覆盖判定拒绿（evidlog.go:322-330）。

**教义的自相矛盾**：adopt.go:132-149 的 DOCTRINE 声称「the transition table rejects any replay the lost line would have made illegal, and a re-dispatch of an external effect is exactly the 14-A5 unresolved first-class case the machine already models」。但 14-A5 的保护是**调用方调用 MarkUnresolved** 才生效（adopt.go:333-339 注释明说 caller asserts）；断尾路径把损坏信息吞掉后，调用方**无从知道**该调 MarkUnresolved。引用保护机制的那句话，描述的恰是一条绕过该机制的路径。

**4-lens**：
- Simplicity：adopt(治愈)/evidlog(拒写) 的「有意分叉」（R9 F2 裁决记录）以一个被证伪的安全性声明换来了两种教义的维护成本——分叉的购买理由已经失效，收敛到 evidlog 式 remember+refuse 反而是**净简化**（少一个教义）。
- Consistency：R9 F2 裁定的理由（「状态机本身是自愈校验」）被现状反例否定——裁决与其 cited 事实不再一致。load.go 的注释甚至称断尾容忍为「a **conservative** compatibility boundary」（:26-27）——解析上保守，安全上激进，一词两用。
- Bearing：邢超探针已给（修前 dispatched 红）；修复方向可探针化（Open 拒绝恢复 / 或 Dispatch 在 tornTail 标志下全量拒绝）。
- Fidelity：如上，注释声称的保护与代码路径不符。

**singularity**：可达坏状态成立（外部受损尾丢失 dispatch 行 → 恢复为 adopted → 再发执行许可；外部效果是否重复取决于宿主与业务 API，但**组件重新发放了它自己的不变量承诺永不重发的许可**——「never auto-retried」adopt.go:9-10 被恢复路径旁路）。更关键的是**问题被重定义**：原问题是「组件保证不重发已可能使用过的执行许可」，采纳现状后问题被偷换为「宿主必须自行察觉组件吞掉的损坏」——而宿主没有任何信号。**判：真奇点级缺陷。**

**裁决：邢超对，且这是三项具体发现中最重的一项**（它击穿的是组件的存在理由，不是某个实现面）。注意他自己的界限声明是干净的：「没有声称探针实际造成重复授信」——只主张许可重发，不主张效果重复。这个分寸他把握对了。

- 夹具 rule 0（judgment-spec-credit.json:47）：「any overdue longer than three months **in the window** denies credit」；time_window（:21）=「six calendar months … both ends inclusive」。**veto 被窗口化，直接反转出处语义。**
- 邢超反例成立：资产 3000 万+近六月干净+两年前逾期四月 → 出处=拒绝，夹具文字=可授 5 万。
- 更糟的一层（邢超点到但可说透）：`_expect`（:112）宣称「the §6.1 gaps (units, window convention, BOTH cutoffs, …) stated as open questions instead of model-authored defaults」——但 units 已填 `USD-millions`（:12）、窗口端点已填 both-ends-inclusive（:21）。**夹具的验收声明与其内容不符**；08:177 明说这些约定属 Project 3 待settled。切点 30/1 与带间区间确实留了开放（:53-55、:90-96——纪律应用是**不对称的**：数字切点守纪律、单位/端点/veto 窗口没守）。

**4-lens**：Fidelity 三连失（veto vs 出处、`_expect` vs 内容、term 定义 vs 自身规则）；Simplicity——若对 veto 同样应用"留开放"纪律（如 coverage 留白待 owner），一个字段就堵住；Bearing——反例可执行（这是判断规格夹具，语义评测即探针）；Consistency——与 L2（owner 责任族）同源：effective_scope 说是 pilot region，但 veto 覆盖期这个真正需要 owner 定的参数没有 owner 槽位。

### P4｜A/B/C ↔ 操作状态直接映射（邢超评论① §4 + 决定 1 vs 05 先验）

**事实**：05:65-73 给出「A 定向补证↔adopted、B 无法判定↔unresolved、C 信任失灵↔conflict」，并断言「件2 状态机**可以直接服务**质证协议，不另造」。而现机器的 unresolved 语义是排他的：「dispatch outcome unknown (timeout / crash)」（adopt.go:58、:8-10）。

**第一性原理判据**：状态机对恢复的价值恰恰是「状态→合法后续动作」的**单值映射**。若 unresolved 既表示"外部执行结果未知"（后续=对账/查询提供方）又表示"证据预算耗尽"（后续=雇主重派/接受无法判定），恢复函数在标签上不再单值，需要状态外的隐藏上下文消歧——状态机的核心价值即告丧失。

**同构的真面目**：快乐路径上 A/B/C 与 adopted/unresolved/conflict 确实相关（谁推进下一步、是否常态），但**失败路径发散**：证据预算耗尽不对应任何操作状态（没有外部请求发生）；执行超时不对应任何质证状态（质证早已结束）。状态机恰在失败路径上挣钱，而同构恰在失败路径上断裂。05 称之为「深层同构、同一状态空间的两面投影」是**把相关性当成了同一性**——类别错误。

**4-lens**：Simplicity——「不另造」是买简，但买到的是状态重载（影子语义），是**假简**；Consistency——05 的映射 vs adopt.go 的 unresolved 定义直接冲突（以代码现状为准：代码自洽，先验越界）；Bearing——邢超的反例（「恢复后无法只根据状态确定该补证还是继续等待」）即思想探针：给定 state=unresolved，合法后续集 = {MarkCompleted, MarkFailed}（机器域）∪ {重派补证、交雇主}（质证域），并集无单值解释；Fidelity——「可以直接服务」：今天没有任何代码服务质证协议（0.2.0 才有图）。

**singularity**：若全盘采纳邢超（三层状态、共享基础设施不共享状态词汇），问题被重定义——从「一个状态机多义」变为「三个小状态机+一份共享事件底座」。**这个重定义是治愈性的**：它恢复单值映射。不存在可达坏状态（他的方案不制造新失败路径）。**判：我方方案在这一点上有真缺陷，邢超的修正无奇点。**

**裁决：邢超对；撤回「直接等同」，保留「共享事件存储/转换库/控制基础设施」——注意这恰是邢超 §4 原文自己让步的形态（「可以共享事件存储、转换库和控制基础设施，不要求三个服务」），双方在终点上其实已经重合，分歧只剩 05 那句话要不要删。** 需要防的过头：不要借此把质证协议膨胀成第三个独立服务——反例修复在文法层就够。

### P6｜「每次人裁产出＝规格补丁」的单向收敛（邢超 §9 + 决定 5 vs 夏元原则 + 05 §四）

**事实**：夏第二轮 §1.4：「人裁的每次产出都应以『规格补丁』形态落回判断规格」；05 §四忠实继承（「人裁不是常设裁决层，是规格的补丁生成器」），且 C 出口（信任失灵）也被框架为「规格失灵」。邢超 §9：坏数据、一次性例外、信任事件、普遍性语义缺陷是四类不同情况，只有适宜复用的结论才进规格候选。

**夏自己的表格已经漏气**：她的三情形表①（利益关联）的产出是「人裁决定规格改写权移交谁」——这是治理动作，不是规格补丁。元原则的**句**比她自己的**表**更激进。05 继承的是那个过强的句。

**系统动力学**：强制每案产补丁 = 个案噪声→全局政策的正反馈通道：案件量↑ → 补丁数↑ → 规格膨胀 → 评审负担↑ → 评审走过场 → 治理失效。延迟长（数月级），存量是"规格条目数"，一旦积重难返无人能读全规格。这正是邢超「防止个案污染全局政策」的原话。

**4-lens**：Consistency——夏之句 vs 夏之表①自相矛盾（以表为准，句越界）；Simplicity——单属路由更简但错属，双属（spec 补丁 / 案件处置记录）是诚实最小；Bearing——探针：一起一次性坏数据案走 C 出口，按 05 须产规格补丁——该补丁**写不出良构内容**（规格没有错），文法强制产出空转，缺陷可机械暴露；Fidelity——05 引用忠实（错在源头不在转译，这次转译无罪）。

**singularity**：问题重定义成立——把信任事件/坏数据塞进"规格失灵"框架是**归因错误**（bug 在演员不在剧本），修复责任被错路由到规格 owner。可达坏状态=规格噪声累积（慢环，真）。**判：邢超对，夏的元原则在语义属内存活、在信任/个案属内越界。**

**裁决：邢超对；修法见第三选项（双属路由 + 复发性测试）。** 注意这同时**支持**夏元原则的核心（事前结构化、规格失灵才上升）——是收窄不是推翻。

## 五、统一病理：转译层的静默默认

九个击穿点（L1-L5、P1、P2、P3、P8，加上 05 的 P4 映射与夏的 P6 越界）在同一层吗？**是——转译层**：两种表示之间的边界上，凡是「源未给定 → 译方必须选值」的地方，选了值却没标记为待决。

**处方**（把既有纪律外溢一个边界即可，不需要新制度）：

## 七、协商系统动力学（把 yaojun×xingchao 看作一个系统）
