## 二、F-01~F-06 逐项裁决（对不对 / 深层结构 / 碰撞点）

### F-01 协作规则归管理面统一治理

**他说得对不对**：原则层对，且生态有实证。claude-sdk 的权限规则来源枚举把 `policySettings` 列为只读的受管理层（sdk.d.ts:5844：「`policySettings`…the set the terminal's /permissions treats as read-only」；sdk.d.ts:9117：「set in managed settings, only allowRead paths from policySettings are used」）——企业规则与管理员/会话/命令行来源分层、受管层只读，正是 F-01 的「统一治理、不被下层覆盖」的先例形态。「智能体不能决定自己的约束」（new-issue L13）与 V0 自己的立场完全同构（05 L93-94 不变量 2：数据面不能写真源、hermes 禁智能体写配置、openclaw 自更新绝不由模型发起）。**「规则缺失时也不能由模型猜一个默认模式继续决策」（L20）是本轮文本里最好的一句**——fail-closed 原则写对了。

**深层结构**：这条把「受控交接默认还是可选」之争从**技术-价值问题**（我方牌 1：不可逆方向应在负担侧，有可辩护的论证结构）移到了**治理问题**（谁有权定默认——答案预先给定为管理面）。技术内容（哪个默认更安全）降级为「供管理面评估的参考」。注意一个细节：**双方此前在这一题上其实是趋同的**（他前轮自己提议「高风险默认受控交接」，见 new-issue L24 自述；我方立场同向）——本轮他把双方共同的倾向一起降格为「参考策略」。也就是说，一个**几乎已收敛的议题被治理重构重新打散**：分歧不是技术性的，是权威性的。

**碰撞点与我方立场**：我方牌 1 的诉求是「显式裁决、勿静默消化」——F-01 给了显式回应，这一点要认。但第一性追问：**「管理面」在协商系统里是谁？** NGA 归属企业（xingchao 方）；管理面在可预见的实践中就是企业侧＝对方。把决定权交给「管理面」，在谈判系统意义上不是引入中立第三方，是**把己方决定权换了一个组织抽象再宣布**。Bearing 探针：规则生产过程本身无任何义务结构——F-01 的管理规则只有「适用范围、版本、共享与隔离要求、补证及偏离条件」（L22），**没有证据义务、没有复核触发、没有撤销与引证程序**。对照：本轮给语义规约配了完整保鲜生命周期（F-04），给夹具配了联合治理与争议保留（对置表后段），给扩展契约配了版本化（F-05）——**唯独规则本身的生产是无治理的治理**。可达坏状态：管理面在无 A/B 证据的情况下发布「低风险域默认 collaborative」→ S1 独立性静默流失，无探针、无告警（组织层可达，非机器层）。

**但有一个对我方有利的文本缝隙**：F-01 只禁止「**模型**猜默认」（L20），并未禁止**组件持有保守底线**。这为我方 P1-1 四层认领中立下的判据（「不可逆方向的一方必须持有保守默认」——我方 11-03 回复一·P1-1 第 4 层）保留了合法位置：**规则缺失时的组件保守底线 = controlled_handoff（0600 的通道类比）**。部署方想放宽，走显式治理动作；想收紧，无需任何动作。可逆性不对称与 umask 案完全同构。这是 F-01 文本内部自带的合流路径，双方谁都没写出来——见第八节第三选项 1。

**裁定**：方向接受（企业治理协作规则是对的、有生态先例）；附加两个不可让条件——①规则生产义务结构（证据义务/复核触发/撤销引证）补齐；②规则缺失时组件保守底线的归属写明。不附条件的接受等于把「谁决定」的答案给了出去、把「凭什么决定」留在桌上。

### F-02 S2 规划 → S1 决策式跳转 → S2 执行

**他说得对不对**：主循环形态（规划-判定-执行-评价-重规划）本身无害且与生态主流兼容。「不要求每条普通边都调用 Jev」「机械控制由框架执行」（L43）与 07 一致。六步里第 4 步「框架检查该判断的适用依据、版本和运行约束，落实合法跳转」（L35）是好的。

**深层结构（本轮最重要的技术发现）**：F-02 第 3 步写「S1……输出结构化判断，**决定应选择的业务路径**」（L34）。这与他自己的重放原则正面相撞：他在 MR!2 评论① §8 白纸黑字写「历史回放**消费当时记录的模型输出**、工具结果、API 观察及有关时间事件，**重跑控制逻辑**……**不要求重新询问模型**并期待逐字相同答案」（/tmp/nga-mr2-comment-197840258.md L136）。两条同时成立只有一种解：S1 的判断作为**记录态 observation** 进卷宗，路径由**声明的（deterministic）判断→路径映射**派生。若路径选择住在模型里（F-02 字面读法），重放就得重问模型——违反他的 §8；若路径由声明映射派生，F-02 的「决定应选择的业务路径」措辞就是错的归属表述。**生态先例站在映射一侧**：langgraph 的条件边 `add_conditional_edges` 的 path 参数是 Callable/Runnable——**路由是声明的代码，不是模型输出**（libs/langgraph/langgraph/graph/state.py:982-1011，签名 `path: Callable[..., Hashable | ...]`）。F-02 的「框架检查适用依据」实际上就是这个 path_map 的影子，但文本把判断与路由捏在同一个动词（「决定」）里。这个歧义必须按「判断为记录态 + 映射为声明态」的方向解掉，否则制品 B（授信时序图）画出来的就是一条不可重放的主线。

**与夏裁决的碰撞（专项见第六节，这里给结论）**：①「当前任务状态」（L34）这个词是漏点——夏两轮的全部价值锚在 S1 输入边界 = 封存件卷宗上；若「任务状态」包含 S2 的活计划/活上下文，锚定通道重开，夏一理由 1（独立视角是 S1 存在的理由）被 F-02 的一个词静默拆掉。②「质证协议本体一字不动，暂不作为共同冻结要求」（L47）——**他是对的，我方要认领**（详见第六节）。

**裁定**：主线形态接受；两项刚性修正——①判定→路径映射归属声明态（消解其与自身 §8 的矛盾）；②S1 输入边界显式定义为封存件卷宗（挂夏一边文法），「当前任务状态」改写为「任务身份/版本与卷宗」。

### F-04 语义规约保鲜

**对不对**：对。「历史版本内容不可改写 / 当前适用性可治理」的二分正是我方钉照版本 + 回放消费当时版本的既有语义（V0 4.2 不变量 3、件 6 重放四模式）。「证据源保留期不自动等于规则的否决有效期」（L88）直接接住了我方 11-03 问 4 的前置子裁决（历史覆盖期不能是无限回看）——他把这个悬案正确地路由进了语义规约治理而非实现方默认。「pending 标记可以支持研发讨论，但不能自动成为正式决策的发布许可」（L88）与我方 pending-confirmation-by 纪律逐字同构。

**生态佐证**：openclaw 对默认值变更的处理是「影响未来会话、不重钉既有会话」（docs/concepts/multi-user.md:133：「Changing a default does not repin existing chats」）——在途任务按旧版继续、新任务按新规则，正是 F-04 在途策略的生态先例形态。

**碰撞点**：几乎没有实质碰撞，这是六项里相容度最高的一项。唯一的结构性残留：「在途任务按管理规则继续、暂停或迁移」的规则归属是管理面，但**规则与在途任务的钉照关系**（任务级 pin 还是域级 pin）没有写——这决定重放匹配键的形态，需要进制品 A。

**裁定**：接受，无保留。

### F-05 原语参照系与行业扩展（含 E1 重写请求）

**对不对与深层结构**：见第五节 E1 专项。结论：**接入权之问对（我方 E1 的表述确有「核心形态限制」的读法空间，他拒绝得有道理）；机器可验证面之问被降级（重写丢了我方关切的另一半）**。他的撤回示例（申请撤回 vs 确认撤回、原请求是否仍可能完成——L105）恰好证明了我方的点：这些区分只有成为**检查器可消化的声明**才是机器义务，否则就是散文义务——而 L4/散文-枚举损耗病（我方 issue#1 五处系统性发现）就是散文义务的历史病历。生态正面证据：MCP 的 `readOnlyHint` 之所以成为 codex 的免批依据（codex-rs/core/src/mcp_tool_call.rs:2595-2612：`read_only_hint == Some(true) → return false` 不需审批；Writes 模式同样依赖该 hint，L2621-2623），正是因为**注释（annotation）是声明却无义务绑定**——「组件声明不自动构成授权」（F-05 L103）他说对了，但他没有说出的镜像句是：**声明若不进检查器，就既不构成授权也不构成约束**——只是装饰。E1/E3 重写后的义务映射若不落为一等 schema 输入，就是第二个 readOnlyHint。

**裁定**：接受；C4 的两个洞并入我方修复计划（与两个 P1 同批），修法方向：取代检查的排序契约挂宿主侧单调版本（效仿 14-A4 的钉照-live 复检但补排序），不是我方能单方闭的口。

## 五、E1 重写请求与 E3 处理专项

### E1：改写保住了关切还是换了问题？

我方原 E1：「开放词汇是否破坏封闭账本」——实质关切是**封闭枚举使八族跨事件规则的机器验证面成立**；我方同一句里已给出兼容出路（核心封闭 + 扩展走独立命名空间/版本代次）。他的改写：「扩展能力如何映射到基础义务」（F-05 L103）。

**判读：换了问题的外壳，保住一半、丢了一半。** 保住的：接入权之问是对的——「封闭核心形态」若被当成生态准入门槛，确实越权（且我方 E1 表述给了这个读法空间）。丢的：**机器可验证面之问被降级为适配契约的内部事务**——「映射到基础义务」若不落为检查器可消化的声明，义务就是散文，而散文-枚举损耗病（L4、issue#1 五处系统性发现）的全部病历都是散文义务造成的。

**我方自己必须先认的一段**：他的「版本化扩展契约」（L103）**实质上就是我方 E1 的兼容路径**（扩展经 schema 版本代次 0.1.0→0.2.0，issue#1 原文）。机制层双方已收敛；纯分歧只剩叙事框架。因此这一项的真实质不是「改写是否可接受」，而是**改写后的义务遗漏**：

**可达坏状态（Bearing）**：行业扩展事件进入共享账本，检查器不认识其状态族 → 或者全拒（= 他担心的接入壁垒，以运行时错误的形式复活）或者跳过（= 我方担心的验证洞）。两个坏状态都可达，除非——**扩展契约是检查器的一等输入**：检查器的规则族参数化自扩展契约（或扩展命名空间自带可编译的规则族声明）。这一点**双方文本都没有写**，是 E1 改写后真正的新增设计义务。生态反面教材立此存照：MCP `readOnlyHint` 是声明却无义务绑定，codex 生产代码据此免批（mcp_tool_call.rs:2595-2612）——声明不进检查器 = 既不构成授权也不构成约束。

**回复建议**：接受改写框架；附加刚性条件「扩展契约 = 检查器一等输入（schema 可编译），否则映射义务为散文」；同时把我方独立命名空间方案作为该条件的第一个具体形态递出（不是退回原表述，是把原表述升级为条件）。

### E3：先查代码现状，再判诉求满足度

**代码现状（逐条核实）**：

1. **持久化状态族里没有 rejected**：ledger.go:29-30——AdoptStatuses = {adopted, reused, **conflict**}；EffectStatuses = {dispatched, unresolved, completed, failed}。「rejected」只是机器**返回值**（adopt.go:79 Outcome.Status 注释「one of adopted | reused | dispatched | unresolved | completed | failed | rejected」），永不入账。

## 七、A/B 实验 owner 安排：三权分布推演

他的安排：模型/评估团队牵头（实验权），组件团队提供双臂，业务与架构方确认指标（参与权），「实验服务于管理规则的制定和复核，**不自动发布规则**」（决策权留在管理面）。加上规则变更权（管理面发布），三权分布是：

| 权 | 归属 | 我方原诉求（牌 3） | 新结构的效果 |
|---|---|---|---|
| 实验权 | 模型/评估团队 | 有人负责即可（哪方牵头都可以） | 满足——owner 落地 |
| 决策权（规则采纳） | 管理面 | 未明确要求 | 明确化——但无证据义务绑定 |
| 规则变更权 | 管理面 | 未明确要求 | 与决策权合一——**闭环内无制衡** |

**对「裁决可证伪性」的影响（核心推演）**：我方牌 3 的原命题是「一个可证伪但无人负责证伪的裁决，等价于不可证伪的裁决」。他的修复**解决了前半（有人负责跑了），没有解决后半（跑了以后算数吗）**。「不自动发布规则」在方向上是对的（防止实验自动改政策——与进化护栏的生态收敛一致，hermes-self-evolution「All changes go through human review」），但**反向护栏缺失**：实验结果与预期相反时，**没有任何条款规定管理面必须消费这个反例**。可达坏状态：夏一证伪开关触发（B 臂判定质量低于 A 臂）→ 报告归档 → 管理面继续按原偏好发布规则 → **一个已被证伪的裁决在系统里继续以未证伪的形态被消费**——这是牌 3 命题的变体：可证伪、有人证伪、证伪了但无约束力的裁决，仍等价于不可证伪。

**他的一个公允技术保留**要接住：「贵方既有配方可作为输入，但要核对其是否适用于真实 Jev 的消费形态；模型替身只验证流程，不能证明真实模型的独立性收益」（L149）——对。夏一的配方产自报告生产线（我们的模型、我们的域）；Jev 的消费形态不同，配方须适配后才有移植效力。这个保留本身是对的，但它同时提示：**配方的适配工作也该有 owner**——目前「核对是否适用」四个字无主。

**第三选项（第八节 3）**：把夏一的**预注册门槛**（双臂差 ≥15 为流程级改动门槛、成本比 ≤1.5× 允差的实例读数形态）从「配方输入」升格为**规则发布门的验收条件**——管理面保留发布权（尊重 F-01），但通道默认这类规则的发布必须附带实验证据包（预注册门槛 + 实测读数 + 反例记录），否则发布无效。**决策权与证据权分离但绑定**——这正是「规则变更的引证义务」（系统动力学任务点名的那一项）的具体形态。
