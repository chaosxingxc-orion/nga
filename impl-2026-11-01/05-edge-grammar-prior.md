# E7：受控交接边文法先验（0.2.0 执行图设计输入）+ evidence_gap 类型提案

> 本件是设计文档（先验），不是实现——0.2.0 图文法升级属正式件战役，本档是其种子。
> 2026-11-01 更新：吸收夏架构师第二轮裁决（三个裁决点全裁完+元原则+四项回执回应）。

## 〇、元原则（设计基础）

**事前结构化优于事中裁量**（夏裁决第五节，与我们六件战役的隐式实践独立收敛）：

> 能在雇佣时刻（无具体案件、无利益冲突）写进规格的，不留到运行期临时判断；
> 运行期必须裁量的，裁量本身也要结构化（预注册门槛、封闭枚举、必填字段）；
> 裁量只在**规格失灵**时兜底，且每次裁量的产出是**修规格**——系统因此单向收敛，
> 越用越不需要人。

三边文法的每一个属性、每一个枚举值、每一个预注册参数，都是这条元原则的实例。

## 一、三边类型（夏裁决命名的文法化）

0.1.0 执行图的边只有结构语义（供给边/依赖边）。0.2.0 增认知关系轴，三种边类型：

| 边类型 | 语义 | 共享规则 | 先例 |
|---|---|---|---|
| `collaborative`（协同白板） | 产出互为输入输出，错误可被互查拦住 | 中间结果共享+复查 | langgraph state channel |
| `adversarial`（对抗隔离） | 对同一问题各出独立结论 | 过程隔离，只围绕结论对抗 | 红蓝队/我们的红队轮 |
| `controlled_handoff`（受控交接） | 产出接力但认知隔离（S2→S1 形态） | 按封闭清单移交可重放可归因产物，移交后隔离，异议走质证 | 夏命名；组装无生态先例（碰撞报告） |

**受控交接边的三属性**：

### 1. `sealed_manifest`（封存件清单）

封闭枚举——进卷宗的每一件都列名，双测试准入（夏第一轮）：
- 重放测试：能否以记录形态复现？不能者不进
- 交付测试：是否为被要求的产出？不是者不进

### 2. `provenance_fields`（来历+足迹+排除记录）

三必填（夏第一轮+我们的碰撞分析确认）：
- **来历**（必填）：S2 为什么采信该证据——非机检，供 S1 判定与人审
- **查询足迹**（必填）：与本证据相关的调用序列引用——**机检**：对件7 取证日志核验声明真实性
- **排除记录**（必填，可为空）：被排除的矛盾材料及排除理由——**机检**：差集告警+非空时供 S1 复核；「没有矛盾材料」必须显式声明（沉默的零 ≠ 声明的零）

### 3. `challenge_protocol`（质证协议）——夏第二轮裁决完毕 ✅

**出口流水线 A→B→C**，转级条件对 A/B 机器可判：

| 出口 | 对应的不完备 | 触发条件 |
|---|---|---|
| **A 定向补证**（默认工作态） | S1 说得清缺什么——能结构化列出缺失的证据类型与理由 | S1 产出了结构化补证单 |
| **B 无法判定**（合法出口） | S1 说不清缺什么，补证无靶子 | 补证轮次达预注册上限，**或** S1 无法产出结构化补证单 |
| **C 信任失灵→人裁**（正交入口） | 分歧不在证据完备性、在信任本身——完整性声明与取证日志互相矛盾 | **人工判定**（账本与声明矛盾=规格失灵，无机器判据） |

**关键细则**（夏第二轮原文的文法化）：
- **补证上限归判断规格预注册**（N 轮），不归判定专家自持（猎人自己决定追多久=失衡）也不归雇主运行期持有（运行期裁量=豁免递归复发）
- **全额回应义务**：每轮补证必须回应上轮质证单的全部要点——部分回应不计入轮次
- **部分回应兜底**：连续 K 轮部分回应（K 由规格预注册）视同预算耗尽，转 B
- **C 是正交入口**：信任失灵不必等 A/B 穷尽——信任层面的分歧与证据层面的不完备是不同维度的失败
- **人裁产出=规格补丁**：每次人裁以「规格补丁」形态落回判断规格，下次同类案件回归字段化通道——递归止住，系统单向收敛

**补证单表述纪律**（防反馈污染，夏第二轮新规则）：

> 补证单只写「缺什么证据」，不写「期望什么结论」。

指定证据类型与来源（「近 12 个月银行流水」），禁写结论方向（「频繁」「异常」「支持驳回」出局）。没有这条，S1 的偏好会顺着补证链回流到 S2——形成「S1 偏好→S2 定向搜索→偏好被确认→更强偏好」的正反馈环。这条纪律把反馈环从正（放大偏差）变为负（收敛到证据本身）。

**与件2 状态机的映射**（碰撞分析发现的深层同构）：

```
A 定向补证  ↔  adopted（正常工作态）
B 无法判定  ↔  unresolved（预算耗尽，等对账/人工决策）
C 信任失灵  ↔  conflict（对一致性本身的质疑）
```

同构不是巧合——是同一个状态空间的两面投影。件2 状态机可以直接服务质证协议，不另造。0.2.0 可选给 conflict 事件加 `spec_patch_ref` 字段（引用产出的规格补丁）。

## 二、evidence_gap 产出类型（判断规格 schema 增量提案）

夏第二轮裁决点②已裁：假设以「待查事项」封存件形态进卷宗，**可证伪性是准入门槛**。

### 完整设计目标（夏的字段组）

```json
"on_evidence_gap": {
  "description": "S2 侧：调查专家的「证据不足/未证实假设」作为结构化封存件进入判断（不是活上下文的犹豫）——可证伪性是准入门槛；S1 可将其作为「无法判定（存在待查事项）」的合法理由引用",
  "type": "object",
  "additionalProperties": false,
  "required": ["hypothesis", "confirm_query", "falsify_query", "stop_reason"],
  "properties": {
    "hypothesis": {
      "type": "string", "minLength": 1,
      "description": "假设陈述：「疑有隐形负债，未证实」"
    },
    "confirm_query": {
      "type": "string", "minLength": 1,
      "description": "能证实它的查询（未执行）：「调取对外担保登记」——S1 可核，雇主可决定是否加派"
    },
    "falsify_query": {
      "type": "string", "minLength": 1,
      "description": "能推翻它的查询——与证实查询构成可证伪性对"
    },
    "stop_reason": {
      "type": "string", "enum": ["budget", "authority", "dead-end"],
      "description": "停手原因：预算/越权/线索中断——供人审与 S2 质量画像"
    }
  }
}
```

### 两条分界线（机器可判，夏第二轮）

1. **与证据通道的分界**：查询是否已执行（在件7 取证日志里查，无需裁量）
2. **与拒收的分界**：可证伪性门槛——写不出证实/证伪查询的假设（「这客户感觉有问题」）拒收，留 S2 侧日志

### 与裁决点①的互锁

待查事项清单是补证单的原料——S1 的质证单可以直接引用「待查事项 #3 未查」，补证单有了结构化靶子；补证单被拒（越权）时，S2 的封存件里多一条「待查事项（越权未查）」。

### 0.2.0 最小实现面

0.2.0 以三字段 `{gap_conclusion, queried, missing}` 起步（消费面：S1 侧已备，S2 侧消费时机=NGA 半场）。夏的四字段为升级目标——一次改动落两个机制（夏自己的建议）：S1 侧引用+S2 侧质量画像。

**interim 闸门缺席声明**：三字段面没有 `confirm_query`/`falsify_query` 的容身之处——裁决点②的「可证伪性准入门槛」在 0.2.0 面上结构上不可实现，这不是豁免而是欠账。interim 补偿：0.2.0 期间凡 `gap_conclusion` 非「已证实/已排除」的假设一律进人工复核（人行使质证权补上机器闸门），不得自动采纳；四字段升级落地前，「可证伪性是准入门槛」由人肉执行，升级后归还字段。

## 三、通道类型作为判断规格字段（豁免递归解）

夏第二轮采纳我们的字段化修法。通道类型是判断规格的一个字段，默认 `controlled_handoff`，规格作者可显式改为 `collaborative` 并**必须**写明理由——豁免从运行期自由裁量变为雇佣期的结构化声明。

## 四、规格失灵三情形（人裁→规格补丁的治理闭环）

夏第二轮给出的「哪些案件必须人裁」答案——不是低风险裁断，而是规格本身无法给出答案的时刻：

| # | 规格失灵情形 | 例子 | 人裁产出 |
|---|---|---|---|
| ① | 利益关联 | 规格作者自免 | 人裁决定规格改写权移交谁 |
| ② | 枚举外案件 | 全新证据类型，封存清单无位置 | 临时定通道+**补进规格枚举** |
| ③ | 无先例风险 | 跨管辖域取证首例 | 同上 |

三条共同点：**人裁不是常设裁决层，是规格的补丁生成器**。不存在「对豁免的豁免的豁免」的链，只有「规格→失灵→人裁→补丁→规格更新」的单向收敛。

## 五、多体拓扑（设计先验，实现延后至 0.3.0+）

夏第二轮裁决点③已裁：**调查侧各自封存+判定侧共享只读并集**。

三条独立性质（判据二在多体下的拆解）：
1. **调查独立性**——各调查专家互不锚定
2. **判定独立性**——委员会成员互不锚定且不被任何调查过程锚定
3. **卷宗完备性**——判定方拿到全部独立证据

两个补丁（缺一则 C 退化）：
- **盲判后合议**：委员会先各自盲判（只看卷宗、互不看结论），后合议（分歧大=自动升级复核）——collaborative 边的时序约束（`phase: blind→deliberate`），不需要新边类型
- **独立互证标记**：并集去重时按内容指纹合并，合并件保留「独立来源计数」——两路独立查到同一证据是置信度加权信号，不是冗余（A 形态下调查早已互染，此信号无从产生）

多体下补证单定向发送（只发被质证的那一路，不群发）——群发等于把委员会关注点广播给所有调查线，未被质证的调查独立性受损。

## 六、术语搭配规则（夏第二轮建议）

受控交接边（边类型）与交接族（动词表）正交：一次受控交接边上可以挂零到多个交接族动词（移交封存件/登记候选/触发补证）。边类型与动词组合才是完整的边定义——后来者不会把受控交接误读为某个具体动作。

## 七、codex 互证记入设计依据

夏第二轮确认：codex 在协同方向开共享、在错误传播方向封口——判据二在另一个框架里的独立结晶。两个独立实现沿同一判据收敛，比任何一方单独主张更接近「这判据抓到了某种客观结构」。
