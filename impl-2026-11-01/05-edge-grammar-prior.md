# E7：受控交接边文法先验（0.2.0 执行图设计输入）+ evidence_gap 类型提案

> 本件是设计文档（先验），不是实现——0.2.0 图文法升级属正式件战役，本档是其种子。

## 一、三边类型（夏裁决第三轮命名「受控交接」的文法化）

0.1.0 执行图的边只有结构语义（供给边/依赖边）。0.2.0 增认知关系轴，三种边类型：

| 边类型 | 语义 | 共享规则 | 先例 |
|---|---|---|---|
| `collaborative`（协同白板） | 产出互为输入输出，错误可被互查拦住 | 中间结果共享+复查 | langgraph state channel |
| `adversarial`（对抗隔离） | 对同一问题各出独立结论 | 过程隔离，只围绕结论对抗 | 红蓝队/我们的红队轮 |
| `controlled_handoff`（受控交接） | 产出接力但认知隔离（S2→S1 形态） | 按封闭清单移交可重放可归因产物，移交后隔离，异议走质证 | 夏命名；组装无生态先例（碰撞报告） |

**受控交接边的三属性**（夏裁决原文的文法化）：
1. `sealed_manifest`：封存件清单（封闭枚举——进卷宗的每一件都列名，双测试准入）
2. `provenance_fields`：来历+足迹+排除记录（三必填——足迹引用件7 取证日志）
3. `challenge_protocol`：质证协议（接收方如何对封存件提出异议并触发补证——出口形态待夏第二轮裁决）

## 二、evidence_gap 产出类型（判断规格 schema 增量提案）

夏裁决 §4「无法判定作为一等封存件」的 S2 侧对齐。判断规格 0.2.0 的 resolution 增：

```json
"on_evidence_gap": {
  "description": "S2 侧对齐：调查专家的「证据不足」作为结构化封存件进入判断（不是活上下文的犹豫）——携带来历与足迹字段，S1 可将其作为「无法判定」的理由引用",
  "type": "object",
  "properties": {
    "gap_conclusion": { "type": "string", "minLength": 1 },
    "queried": { "type": "array", "items": { "type": "string" } },
    "missing": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["gap_conclusion", "queried", "missing"]
}
```

## 三、通道类型作为判断规格字段（豁免递归的解）

夏裁决边界声明「按案件风险分级开豁免」有递归风险（谁裁低风险）。解：通道类型是判断规格的一个字段，默认 `controlled_handoff`，规格作者可显式改 `collaborative` 并必须写理由——豁免进现有规格机制（schema 声明），不开新裁决层。

## 四、验证税预估（碰撞报告修正：9 格文法的税基）

三边类型 × 三属性 = 9 格。碰撞报告建议：参数化优先（属性是可选字段而非每格必填）、逐格夹具、纸面格 schema 层拒绝。0.2.0 战役的夹具预算按此规划。
