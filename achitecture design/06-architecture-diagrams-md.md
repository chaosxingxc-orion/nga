## L1 全景：agent-festival 在整个系统里的位置

```text
              企业边界外
  监管机构            客户（面客智能体）           其他企业
     │                    │                        │
     └──────── L1 协议层（A2A）：委派 / 两类超级智能体 / 跨行桥 ────────┘

  ┌───────────────────── 企业内 · 一份管理面 ─────────────────────┐
  │                                                              │
  │   员工 User（责任主体，经岗位 Role 拿授权集）                    │
  │     │ 发起任务（授权集 = 这个 Task 的根权限）                    │
  │     ▼                                                         │
  │   岗位智能体（超级智能体 · 统一入口）◄── 面客智能体（第二信任边界）│
  │     │ 检索专家 / 专家团                                        │
  │     ▼                                                         │
  │   L2 能力目录：专家契约 · 专家团记录（执行图）· 工具 · 知识源     │
  │     │ 规约翻译层：岗位包 / Skill / 组件包 → 契约四段（草稿）      │
  │     ▼                                                         │
  │   L3 能力契约（四段）＋ 合成与判定：整体所需 ⊆ 员工持有           │
  │     │ 签发短期令牌（预算切分；子任务权限 ⊆ 父任务）               │
  │     ▼                                                         │
  │   L4 任务树 / 编排：执行图驱动专家团；三态共享（草稿→封存→揭示）   │
  │     │                                                         │
  │     ▼                                                         │
  │   数据面：模型循环 ＋ 强制点（两层）──► 工具 / 数据 / 资源        │
  │     │ 每次工具调用发事件                                        │
  │     ▼                                                         │
  │   问责账本（只追加）：归因锚 = 持签名身份的 Agent；               │
  │                      责任主体 = User；采纳是一等事件             │
  │                                                              │
  │   底座：openJiuwen（Java 内核与运行时）                         │
  │   授权真源：行内身份与权限系统（本设计不另造）                    │
  │   规约层（外部三仓）：EA 岗位包 / GRACE │ FSE Skill │ FAH 组件包 │
  └──────────────────────────────────────────────────────────────┘

  管理面三真源 = 目录 + 策略 + 账本（人对着它们工作，天级）
  控制面无自有真源：读管理面、写账本（确定性代码，准入时刻）
  数据面无真源：持令牌执行（调用时刻）
```

L5 能力市场（Agent Skills 类生态与企业间桥）在 S2 之后，未设计。

## L2 核心模块：一次任务的九步走法（以「监管报送」样例为例）

```text
  员工小王（合规专员）
    │
    │ 1 发起      对岗位智能体说「提交本季度监管报送」
    │             开 Task；小王经岗位拿到的授权集 = 根权限
    ▼
  L2 目录
    │ 2 召回      命中专家团记录「监管报送团」：两个节点（文档抽取专家、
    │             报送专家），一条边（抽取结论供给报送），先抽取后报送
    ▼
  L3 契约
    │ 3 合成      两份契约 → 一份整体契约：授权取并集（读收件箱 PDF、
    │             执行 OCR、委派抽取专家、往监管网站写〔不可逆〕、读密钥）；
    │             副作用取最严（不可逆）；预算串行相加
    │ 4 判定      整体所需 ⊆ 小王持有？是 → 放行；否 → 整团在启动前被拒
    │             （不会跑到一半才发现缺权限）
    │ 5 签发      每个节点拿自己的短期令牌（根权限的衰减）；并行节点预算切开
    ▼
  L4 执行
    │ 6 执行与共享 抽取专家在私有草稿干活 → 结论写入槽位即封存；
    │             报送专家被签发时才读得到（揭示）；草稿永远读不到
    │ 7 人在回路  报送是不可逆且无补偿动作 → 回小王审批
    │ 8 验证      验证者 = 同一智能体下的独立上下文，只读结论，结构化输出
    ▼
  账本
      9 记账      每次对草稿与槽位的读写、验证结论、采纳与否，
                  全部带（会话，专家，岗位）入账；顺会话可追到小王
```

三面视角与九步的对应（同一份声明式文档在三个时刻被谁动）：

| 面 | 时刻 | 谁在动 | 对应九步 |
|---|---|---|---|
| 管理面 | 编写，天级 | 技能作者、目录管理员、合规官、审批人 | 第 2 步的目录内容在这里被编写与审批 |
| 控制面 | 准入时一次 + 每节点调度时签发 | 确定性代码 | 第 3、4、5 步 |
| 数据面 | 每次工具调用 | 模型循环 + 强制点 | 第 6、7、8 步；第 9 步写账本 |

## L3 机制明细：每块是什么、状态如何

| 机制 | 一句话 | 状态 |
|---|---|---|
| 能力契约四段 | provides（能做什么）/ requires（要什么授权：资源×动作×副作用矩阵）/ effects（改变什么）/ bounds（预算上限） | 已完成：schema 0.1.0 + 双向样例 5 必须通过 + 15 必须拒绝 |
| 签名与信任 | 契约是独立签名文档；信封复用 A2A AgentCardSignature；多签必须全过；签名人与主体绑定 | 已完成：样例 2+16、密钥库 0+3 |
| 执行图与合成 | nodes（专家契约）/ edges（结论供给）/ plan（顺序与并行）；授权并集、副作用最严、预算求和 | 已完成：合成器 + 样例 8+28，含治理样例（管理员发布必须通过、流水线必须拒绝） |
| 授权衰减（中心约束） | 判定一句话：整体所需 ⊆ 员工持有；子任务权限 ⊆ 父任务；业界分歧点，本设计自选并双向测试承重 | 已完成（判定与合成已机器化；业界无逐任务合成签发先例） |
| 预算签发时切分 | 并行分支在签发子令牌时切预算，不用共享计数器（消除检查-使用时间差竞态）；可切分与不可切分两类量分开 | 已完成（0.1.0 均分；业界无按图切分先例） |
| 三态时序协议 | 草稿 → 写结论槽位即封存 → 消费方签发时揭示；`task://` 授权由图派生、手写即拒、默认即隔离 | 已确认：两位架构师书面确认；机器形态为零（文法、派生函数、封存强制未实现） |
| 工作池模式 | 并行组声明为池：组内开放、组外沿边、出组封存、只追加 | 已确认（架构师 A3）；形态未做 |
| 问责账本 | 归因锚 = Agent、责任主体 = User、采纳一等事件、读写带三元组 | 锚点已定：事件 schema 未建 |
| 治理即任务 | 发布契约 / 批入目录本身是一次 Task，走同一判定与账本 | 已完成（治理样例已过合成器） |
| 三面视角与四不变量 | 同一份文档三时刻投影；确定性住控制面、数据面不写真源、任务钉准入版本、强制点两层 | 倾向：待架构师确认（E1–E4） |
| 规约翻译层 | 岗位包 / Skill / 组件包 → 契约四段的编译规则；副作用枚举收敛（只许收紧）；空 bounds 即拒绝 | 映射表已成稿（2026-10-29 草稿，未实现） |
| GRACE 上下文接口 | 需求侧最小 schema + 准入读回 / 执行消费 / 审计记录三个消费点；不复刻实现 | 接口稿已成（草稿）；上下文整体仍是缺口 |
| 宿主接入条件 | 七类放宽通道逐条声明 + 准入时读回实际生效策略核对 + 三条身份默认 | 表已成稿（草稿）；采纳待架构师 |
| 动态主线 | 吊销与新鲜度、认证凭证钉制品摘要、账本读出、持续核验、撤回回滚 | 未设计（令牌路线待裁定，是最大悬案的下游） |
| 边界外主体 | 监管强制事件、客户适当性、执业资格、对等协作 | 未设计（已整理为裁定题） |
