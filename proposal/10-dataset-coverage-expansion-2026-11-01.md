缺陷映射是本项目的实验设计，不是数据集作者的结论：Kev 扩展重点检验 defect 2/10；Typed Decisions 与 Open-Jev 的定义/类型任务对应 defect 1/8/17；BEV 数值和反事实对应 defect 4/10/12；多语言定义与网页状态任务分别对应 defect 17 和 10/14。每个具体 measure 在接入登记时还须固定对应子集和判别对照，不能用这层映射声称全部缺陷已被覆盖。

上述数量和任务描述来自本地数据卡，不是本轮重新计算的样本统计或模型成绩。数据卡与源码也需针对性审查，不能把目录存在或 `.complete` 当作科学准入。

## 推荐的实验顺序

1. **保留当前轮作为明确的窄域锚点。** 不终止在跑实验，不把新增数据混进已冻结训练；保留原始两套 TEST 的验收口径。
2. **先补已有模型的直接驱动评估覆盖。** 对已确定的模型与新增任务建立明确矩阵：每格写模型版本、任务版本、原生指标、适用类型、是否支持和状态。缺格标缺格，不以不同温度或重复任务凑覆盖数。
3. **在第二轮训练中扩展数据，而不改第一轮。** 初步优先 Typed Decisions、BEV 和 Open-Jev v1.1 的允许训练部分。冻结混合比例、去重规则、独立 DEV 与测试来源隔离，再比较同骨干 K0、原窄域 K1、广覆盖训练 K1。先以 0.8B/2B 验证接入与增益，按原规模计划推进 4B/9B。
4. **先登记评估，再运行模型。** 公布每套原生统计；scenario-macro、question-micro、按 family macro 等不一致口径分列。准确率、Brier/ECE/NLL、ordinal MAE、成对鲁棒性各保留适用分母。新增报告不能取代原有 TEST 门槛。
5. **分别报告域内收益、迁移收益和鲁棒性。** 混入训练的数据集与未见任务分开。首次查看后的测试集如被用于继续选方案，就只能明确标为开发证据；下一次泛化声明需要新冻结的未用测试。
6. **CPU 接入与 NPU 运行并行。** 数据卡/来源盘点、adapter 与指标验证先完成；合格新增推理入队，在资源可用时接续。没有就绪任务时如实报告空档，不重复无效实验填卡。

## 执行清单与完成标准

| 顺序 | 交付 | 完成标准 |
| --- | --- | --- |
| A：覆盖与来源清单 | 逐个登记本地 24 个目录，区分独立来源、衍生子集、版本、结果包和模态 | 每项都有纳入、延后或排除理由；分别统计来源族、任务族和模型×任务单元，不能把目录数当独立数据集数 |
| B：评估接入 | 优先补齐候选在 Kev hard/documents/devtools 上的比较，并核查 Typed Decisions、BEV、Open-Jev v1.1、DecisionPivot core、DecisionRobust 文本的指标接口 | 固定版本、split、mask、分母、原生指标及额外指标；对重复来源和已暴露 TEST 作显式标记；参考工作没有可比数字时留空 |
| C：新增推理队列 | 对已选模型生成明确的 N×M 状态矩阵 | 每格标明已有结果、待运行、来源重叠待核查或不支持；先完成前瞻评估登记，再将就绪任务异步入队；继承十分钟模型巡检与脱离会话运行规则 |
| D：下一代训练数据 | Typed Decisions、BEV、Open-Jev v1.1 中可用训练部分的混合方案 | 来源/场景/规则族去重，保留成对关系，DEV 与 TEST 隔离；公开测试分数和参考对齐汇报后，再讨论并冻结混合比例与训练方案 |
| E：收益报告 | 同骨干 K0、原窄域 K1、广覆盖训练 K1 的分任务比较 | 域内测试、未见来源迁移和鲁棒性分表；保留原生口径与不一致口径，不用一个总平均掩盖退化；原轮指标与验收门槛原样保留 |

“先汇报公开测试指标，再讨论训练计划”仍然成立。可以并行准备训练数据的来源和划分，但不把这份候选清单视作已经确定下一轮训练混合。已有参考 TEST 的汇报也不等于可以反复用候选 TEST 分数挑选训练方案；候选选择仍在 DEV 完成。

参考模型的原生测试覆盖已经宽于我们自己的训练收益验证。扩展既要补新任务，也要补相同任务上的模型覆盖，避免每个模型只在自己的原生数据集上取得一个不可直接比较的数字。优先沿用既定模型名单，先扩任务轴；模型名单是否扩展另行依据覆盖缺口判断。

## 防止扩数据后仍学捷径

扩数据的无约束最优可能仍是记住标签、来源格式或生成器规则。因此每条学习目标须落到缺陷登记项，并保留常量、question-only、空 input 和合适的反事实对照。训练/DEV/TEST 应按原始来源、场景、规则族或网站分组；规则文字改写不能自动视为新独立样本。所有不变性目标都配判别任务，不以恒定预测获得的稳定性充当收益。

中文专家定义、规则版本变化、跨问题重新划分、未知与 fallback、记录和观察冲突、非技术人员编写模板仍有覆盖缺口。公开集只能承载其中部分；业务缺口数据需要后续独立定义，不将公开 benchmark 的提升直接称作真实业务收益。
