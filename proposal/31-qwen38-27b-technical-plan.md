# Qwen3.8-27B 技术方案与执行依赖

更新：2026-11-06。用户明确要求27B加入当前技术方案；本文件将其从远期候选提升为与0.8B/2B/4B/9B并行准备的正式分支。八路小模型训练已完成，DEV 与正式 TEST 接续仍在推进。当前方案规定研究顺序，不替代具体实验的预注册，也不宣称27B训练或公共TEST已经完成。

## 模型身份与比较原则

采用用户指定的 `Qwen/Qwen3.8-27B`，本地 `/mnt/cephfs/models/Qwen3.8-27B`，固定上游版本 `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`。发布说明将其描述为经过后训练的图文模型；这里的“基座”指我们继续优化的起点，不将它标成未经后训练的Base。当前只研究文本决策。不得替换为Qwen3.5、量化或推测解码变体。

0.8B–9B是Qwen3.5 Base，27B是另一发布版本和训练状态，因此两者对比是候选系统对比，不能单独归因于参数规模。27B训练收益必须与它自身未经我们更新的起点模型，在相同TEST问题、接口和统计口径下比较。

## 当前证据

四卡真实任务评分已限定验收：175 物理卡0–3，FP32、SDPA、HF32关闭，五条冻结DEV输入×三条件全部完成，共723次候选前向，最长1033tokens。full、blank、question-only准确率分别为2/5、0/5、0/5；控制预测相同但五组数组均不同。预选单个保存logits的CPU归约通过固定容差，不是独立模型前向。实际exit0且四卡已释放，359项分析断言及142项独立检查通过。镜像仍为 `sha256:8190b3ec51929baca2388452039ccf05d681c01b7c91cc55dd1e7ac5570a76b7`。这些结果不证明总体效果、公共TEST、两卡容量或反向训练可行。历史21–22token探针的读数单列保留；见[已验收工程范围](https://github.com/chaosxingxc-orion/nga/wiki/Qwen38-27B-Engineering-Forward)。统一rc1镜像不自动继承另一镜像的资格。

## 技术路线

| 阶段 | 27B工作 | 交付与进入条件 |
| --- | --- | --- |
| 第一阶段：工程与参考基线 | 复用已运行四卡推理路径，配置化接入；先验证实际任务长度、候选读出和数值有效性，再做固定参考推理 | 首批对齐decision-v7与transfer-v4；后续加入已准入的BEV和其他公共任务。具体掩码、样本数、指标、温度及prompt在每个任务执行前固定；不同协议单列 |
| 第一阶段：学习方法基线 | 四卡分片冻结权重+LoRA；先完成真实前向、反向、参数更新、保存与恢复的最小验证，再启动固定训练 | 复用现有TRAIN/DEV划分及可比较的任务定义；27B实际recipe单独冻结。保留两个seed；DEV决定允许的配置，冻结后才做最终TEST |
| 第二阶段：System1业务任务 | 与小模型一同测试新业务数据、typed readout、拒答/未知和决策配对一致性 | 按业务要求补齐数据与评测；每个不变性目标配套区分性任务，不以aggregate accuracy代替一致性 |
| 第三阶段：系统级学习 | 纳入RL候选；可研究27B向小模型蒸馏，或作为更强决策模型 | 依赖前阶段稳定轨迹与系统采集。蒸馏教师能力、收益及成本是待检验假设，不预设27B优于小模型 |

第一阶段测量承接proposal既有R0/R3/R6与defect12测量要求；具体业务改进需在预注册中指向缺陷登记表的对应行。常量、问题孤立和空输入等退化对照沿用适用协议；不能用高准确率代替区分能力验证。参考工作原生温度与T=1、不同mask、不同接口分别报告。

## 资源与排队

默认申请175四张卡作为一个资源组；两卡是经实际DEV显存和吞吐验证后的候选，不为节省卡数反复调试。训练采用模型分片/FSDP类可训练实现；普通复制式DDP不能解决单卡模型容量，推理device_map也不能证明反向可用。暂不扩展为全参数训练。

保留正在运行的实验。27B后续具体任务准备好后，先让指定卡完成当前任务，再暂缓向该资源组补充单卡后继，凑齐四张空闲卡后整体启动；其余卡继续消费队列。仅在27B可执行时才收拢资源，不能提前长期留空。四卡任务存在短暂集齐等待，不能承诺任何时刻八卡均满载。优化目标是有效实验吞吐和总卡秒，而不是无意义重复任务制造占用。

CPU评分与结果分析异步执行，释放NPU后继续下一项推理；数值评分用脚本并行计算。监控由脚本读取日志、心跳和退出标记，事件触发加600秒兜底。超过一分钟的任务分离运行、保留容器和Ceph日志、可恢复，提供准确重启命令。

## 工程边界与当前待办

只有一个 `engineering-base-rc1`，不因27B新增一系列产品版本。模型、数据、资源和入口通过配置输入。复用已工作路径并记录确切镜像；统一镜像接入只修真实依赖和功能缺口，不追加权限隔离、管理员级custody等加固门槛。

1. 五条DEV工程试跑已完成并限定验收。复用其已验证的模型加载、候选续文评分与释放路径，不重复该探针；准备完整参考任务的固定协议和配置。
2. CPU准备可训练LoRA分片配置及最小更新/保存/恢复任务。只有准备完成并通过具体功能审查才收拢四卡，现有任务的CPU评分不构成资源依赖。
3. 完成27B起点指标；同时完成LoRA实际训练路径，冻结训练recipe。
4. 两种子训练→DEV→冻结最终名单与评测计划→同TEST→CPU统计→独立结果复核。

目前已授权模型和2/4卡资源，不需用户再次确认。实际任务级最小推理已完成；剩余缺口是完整参考任务协议与可训练的分片路径。没有27B训练速度实测，暂不给出无依据的完成时间。配置任务图见[计划清单](../configs/experiments/qwen38-27b-plan.json)；其中planned/blocked节点不是已可执行队列。
